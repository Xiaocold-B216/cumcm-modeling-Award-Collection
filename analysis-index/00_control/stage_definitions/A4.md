# A4: Annual test baseline execution and A3 finding validation

## Scope and dependency

- Depends on A3 being `passed`.
- This stage only executes, measures, validates, and classifies. It is not a broad repair stage.
- Stop after A4 remote readback. Do not execute A5.
- Do not re-run A1, A2, or A3, and do not amend or overwrite their history.

## Objective

Run the 2015-2025 annual tests, establish a real runtime baseline, and validate every A3 audit finding. Each finding must be classified as one of: `confirmed_defect`, `intentional_behavior`, `false_positive`, `requires_human_review`, `deferred_with_reason`, or `out_of_scope_for_A4`.

## Authoritative inputs

- `analysis-index/00_control/test_integrity_audit_2015_2025.json`
- `analysis-index/00_control/test_change_justification.md`
- `tests/test_2015_manual.py` through `tests/test_2025_manual.py`
- Current dependencies, gates, checkpoints, annual reports, queues, `progress.json`, schema, business outputs, and source materials.

Gates, checkpoints, reports, queues, `progress.json`, schema, and business outputs are read-only inputs. A3 recommendations are hypotheses and must be checked against current source, inputs, and runtime evidence.

## Allowed outputs

- `analysis-index/00_control/a4_test_execution_summary.json`
- `analysis-index/00_control/a4_test_failure_inventory.jsonl`
- `analysis-index/00_control/a4_test_runtime_profile.json`
- `analysis-index/00_control/a4_a3_findings_validation.md`
- `analysis-index/00_control/a4_stage_report.md`

Keep full logs and temporary cache outside the repository. JSON must be UTF-8 without BOM, end in LF, parse strictly, and contain no `NaN` or `Infinity`.

## Forbidden writes

Do not modify `tests/`, business facts, original papers/archives/images/data, `analysis-index/01_inventory/` through `analysis-index/09_checkpoints/`, `progress.json`, the global review queue, or missing-segment requests. Do not add `skip`, `xfail`, or `errors=ignore`, delete assertions, or lower precision.

## Required execution

1. Check Python, pytest, dependencies, branch, HEAD, worktree, and all 11 annual files.
2. Set `PYTHONDONTWRITEBYTECODE=1` and disable pytest cache.
3. Run collection for all 11 annual files first; save complete output outside the repository.
4. Run each annual file independently and record exit code, passed, failed, skipped, errors, duration, and failure IDs.
5. Validate skip conditions, `errors='ignore'`, BOM versus no-BOM output policy, page and worksheet bounds, queue/progress mixing, and empty CSV/JSON/JSONL behavior.
6. Use two independent evidence paths for suspected defects. If evidence conflicts or remains insufficient, mark `requires_human_review`.
7. Validate outputs, worktree, commit, push, and remote readback.

## Acceptance

All 11 files must collect successfully or have an explicit collection blocker. Every year must actually run with an independent exit code. Results and failure nodes must be structured. All high-risk A3 findings must receive an allowed classification. Tests and business facts must remain unchanged. Commit, push, HEAD alignment, `git diff --exit-code`, and key-file byte readback must pass.

Test failures may be recorded without blocking the framework, but the report must never claim that all tests passed. If the status enum only permits `passed/blocked`, use `passed` only when the baseline is complete and record failures explicitly.

## Blocked reasons

`missing_dependency`, `pytest_collection_failure`, `environment_failure`, `missing_test_file`, `unreadable_input`, `network`, `authentication`, `permission`, `remote_divergence`, `human_review_required`.

## Stop rule

After A4 remote readback, stop. Do not execute A5 or any later stage.
